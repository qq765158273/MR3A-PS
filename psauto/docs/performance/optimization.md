## 实现

- 常驻一个 Node 客户端，加载**配置指定的实际 CLI 安装**中的官方 Registry、Session 和参数解析模块。每条命令继续调用官方 `Session.run`，保留版本检查、命令处理和浏览器 daemon。停止时只结束本项目客户端，不退出浏览器。`cli_persistent_client:false` 可选择原单次启动模式作诊断对照。
- 在输入适配器中支持 Windows Forms `Keys` 的修饰键标志，仍使用 Maa 原生 `ClickKey`。例如 `0x2000D`（JSON 十进制 131085）为 Ctrl+Enter，`0x20073`（131187）为 Ctrl+F4。Record JSON 将 Ctrl+O、Ctrl+N、Ctrl+S、Ctrl+Enter、Ctrl+F4 和 Shift+End 的三节点改成一次按键请求，结束时用 `finally` 释放修饰键。
- Record 的节点前延迟设为 0；已经通过识别的 `DoNothing` 节点不额外睡眠。输入后的原有等待、全部属性后确认、身份/保存/Build/空白台检查保留。Build 的初始 3 秒和最多 60 秒等待保持。
- 节点和识别事件共享相同像素的截图文件，以识别 ID 和像素摘要复用，PNG 使用无损快速压缩。逐步日志与失败截图都保留，只改变文件引用；不再为同一幅画面重复编码、写文件。
- MCP 的本机证据中新增 `timings.json`，分别记录 Pipeline、证据导出，以及每次控制器请求的时间。传输计时只包含操作种类与毫秒数，不记录代码、输入文本、URL 或登录信息。
- 证据导出自动生成 `summary.json`，并把每个节点的识别、动作和总耗时写入 `report.json`。这些汇总直接来自 Maa 的 `ContextEventSink` 原始 `Node.*` 事件；外部 CSV 只用于跨运行对比，不是成功判定来源。

## 隔离验证

常驻客户端的当前浏览器只读补测：首次空命令约 1450ms，后续约 998–1001ms；三次原始截图约 999–1003ms。原单次启动客户端的上一组样本约 2 秒；这些小样本不替代完整对象验收。

7 项 CLI 集成、5 项剪贴板/连接集成、原生图像回归、参数/服务/MCP 回归与 schema 校验通过。补充用例验证了组合键确实以 Ctrl+Enter 到达临时测试页面，停止客户端后浏览器仍可操作，以及客户端超时不会重放或继续发送输入。

对旧 REC4 原始帧做导出回放时，新导出器用约 13 秒保存 106 张不同画面，226 个节点和 1848 条事件保留，所有节点和事件截图逐像素相等。旧运行目录有 473 张 PNG；文件数量不代表识别次数，重复画面现在共用路径。

## 校准过程中保留的失败

首轮 GM_MCP_REC5 在查重名称检查停止：OCR 将末位 5 读成 S；第二轮 GM_MCP_REC6 将末位 6 读成 E。两轮均在创建之前停止，未保存对象，DBX 确认定义不存在。证据分别保留于 `out/objects/20261104_203013_480366/` 和 `out/objects/20261104_203219_476963/`。

对同一个 REC6 输入框按 Tab 移开焦点后，严格名称 OCR 通过，定位到插入光标对末位字符的干扰。因此在 Record 的 JSON 中加入 `query_name_blur` 再进入原名称检查，没有把 E/6、S/5 做模糊替换，也没有去掉名称保护。真实前后裁剪已加入原生图像回归；失败窗口通过已有取消 Pipeline 关闭并确认空白台，才允许重新发起完整调用。

随后 REC6 的完整调用在 Save As 名称校验遇到同一光标问题，于 `R_Save_name` 停止。保存名称也加入 Tab；焦点移到 OK 后，原文字 OCR 将其读成带额外字符的 `OK`，改为复用 Field 已验证的 `save_as_title.png` 和 `save_as_ok.png`，阈值 0.85。Build 名称的原 165×70 ROI 会把无光标的 6 也读成 E；两处 Build 身份检查同步缩为 165×25 的单行，保留原精确名称规则，真实截图回归通过。

REC6 在上述剩余节点分段校准后完成保存、Build 和关闭，不计完整调用成功。该次完整失败为 `out/objects/20261104_203522_630973/`；收尾校准目录依次为 `out/runs/20261104_204425_646013/`、`20261104_204628_788374/`、`20261104_204809_800327/`、`20261104_205014_802033/`、`20261104_205129_910528/`。其中一次校准携带旧参数绑定，仍使用旧 Build ROI，随后重新绑定才验证新 ROI。这些失败与分段结果均保留，不改记为完整成功。
